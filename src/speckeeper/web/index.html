AI made shipping faster. Specs can’t keep up.

Spec Keeper is an agent in your team's Slack. It turns what a meeting or a thread decided into requirements, writes the PRD and GitHub issues once someone approves, checks every criterion in CI, and flags tests that still pass against yesterday's spec.

I
The problem

AI lets teams ship faster than anyone updates the spec. Decisions are made in a meeting or a Slack thread, and they never reach the PRD, the tickets or the tests.

So the tests stay green while checking last week's rules. Spec Keeper sits where the decisions happen and keeps the PRD, the issues and the CI results in step with them.

VII
Trust

Grounding, guardrails and security.

Cited or dropped. Every requirement names its Slack message or meeting time; anything Gemini returns without a citation never reaches a card.

Known sources only. Only the project channels it's set up for (anywhere else it says so and reads nothing), meeting notes shared with its account, and CI results from the repo's workflow.

The agent only reads. Three tools over Firestore: requirements, criteria with CI status, change history. It can't change anything, and every tool call is checked and audit-logged.

A person approves. Nothing is written before someone clicks Approve, and approvers can be limited to named people. Each proposal is claimed in one Firestore transaction, so a double click files it once.

Injection-resistant. Rules in Gemini's system instruction, messages fenced as data: 3 of 3 attack messages blocked on real Gemini.

Safe output. Text from people, Gemini or CI is escaped before it reaches Slack, so cards, open questions and CI summaries can't @channel or post links; mentions are defused on GitHub.

Locked-down endpoints. Slack requests are signature-checked. The CI webhook checks its secret before reading the body, takes at most 3 MB, and posts only where requirements were captured.

No message text in analytics. BigQuery, Cloud Trace and Memory Bank keep counts, names, timings and versions, never questions, answers or notes; checked on the live rows.

Recoverable and audited. Firestore keeps 7 days of point-in-time recovery with delete protection, and every read of a secret is logged.

Supply chain. Every change runs the tests, a lint check and a dependency audit in CI; GitHub Actions are pinned to commit hashes, and Dependabot watches for updates.

Least privilege. Secrets live in Secret Manager, readable only by Spec Keeper's service account; there are no service-account keys. Refused requests and the daily Gemini budget email an alert.

Demo-safe. Anyone can start clean with reset demo, but not while someone else is in the middle of a run.

Security-reviewed. On 16 Oct the code, the Google Cloud setup and the dependencies were reviewed; the code fixes shipped with regression tests, and no secret has ever been committed.
