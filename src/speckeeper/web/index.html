The spec changed in Slack. Nobody told the tests.

Spec Keeper closes that gap. It turns what a meeting or thread decided into requirements, writes the PRD and GitHub issues once someone approves, checks every criterion in CI, and flags tests that still pass against yesterday's spec.

Where to look for each criterion

TECHNICAL MERITThree Gemini roles, one service

Gemini 3.1 Pro captures requirements with cited sources, a Flash triage agent watches threads, and a Google ADK agent answers questions with read-only tools. Cloud Run, Firestore, Secret Manager. Code and tests.

PROBLEM AND IMPACTSpecs fall behind fast teams

AI lets teams ship faster than anyone updates the spec. Spec Keeper keeps the PRD and GitHub issues current from where decisions actually happen.

INNOVATIONStale tests

A test that still passes against an old version of a requirement is flagged, not counted green. See the table below and the CI runs.

USER EXPERIENCEAll in Slack

One card per meeting, one click to approve, a suggestion only when a decision changes, and @Spec Keeper mute to stop it.

Green isn't proof if the test is out of date.

Each test carries the version of the criterion it was written for. When the team changes REQ-7 from 25 MB to 8 MB, the old test keeps passing, and Spec Keeper reports it as stale until someone updates it.

How it works

Nothing changes on its own

Gemini only proposes. The PRD and issues change when a person clicks Approve, and every requirement cites where it was agreed.

Known limits
  • CI runs come from the checkout-app repo, which judges can't push to; the stale-test loop is shown in the video and the CI history.
  • Gemini 3.1 Pro is in preview with a small quota: at busy times a capture may need a retry.
Demo data

The team, the meeting and the checkout app are made up. Messages posted in the demo channel are sent to Gemini on Vertex AI.
